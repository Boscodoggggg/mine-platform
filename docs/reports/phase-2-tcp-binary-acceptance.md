## 1. 结论摘要

本切片交付了 MQTT JSON 之外第一条可复现私有 TCP 二进制纵向链路。第三方协议通过稳定 Java ABI 描述有界帧、每连接会话、严格解码和 ACK；
注册表以标准 ServiceLoader 校验协议键唯一性和 API 主版本。仓库矿卡示例固化 51 字节黄金帧、CRC16-CCITT-FALSE、字段范围、十进制缩放
和 13 字节成功 ACK，不对应任何真实厂商或行业协议。

Gateway 在插件前完成 TLS、全局/单来源连接配额、读空闲和长度字段拆帧；每个连接独立会话，首个有效帧绑定完整身份快照中的平台设备，
后续身份切换关闭连接。协议解析和同步 RabbitMQ publisher confirm 在专用有序业务线程执行，只有发布确认成功后才生成 ACK；解析、身份、
发布或 ACK 编码失败均关闭连接且不确认，使设备可以按原 `bootId + sequence` 重传。

真实设备、厂商报文、真实证书、矿区网络、容量、重连风暴、双 Gateway、断电、备份恢复、原生 mTLS/设备证书身份和 24/72 小时长稳
按当前要求未执行或未实现。本报告只能证明仓库代码、回环网络和容器化自动化基线，不能作为矿区上线签字或对外销售终验凭证。

## 3. 关键运行不变量

1. TCP 监听器应用默认关闭，启用必须显式绑定一个已离线审核的协议键。
2. SPI 不向插件注入平台框架和基础设施对象，但同进程 JAR 不是安全沙箱，必须在镜像构建前审核。
3. Netty 在插件解码前执行最大帧限制；插件不能接受无界输入或自行改变连接配额。
4. 帧内身份不能直接成为平台 `deviceId`，必须从原子完整身份快照反查并匹配插件实际版本。
5. 一个连接只允许一个平台设备身份；身份切换不会产生遥测或 ACK。
6. 每连接事件在专用业务执行器中保持顺序，阻塞 publisher confirm 不占用 Netty IO 线程。
7. ACK 只证明统一遥测已获得 RabbitMQ publisher confirm，不代表最终入库或业务处理完成。
8. 失败无 ACK，设备按原启动周期和序号重传；平台既有 Inbox 继续承担最终幂等。
9. TLS 私钥只通过绝对路径只读 secret 加载，不进入镜像、环境变量、日志或验收样本。
10. 指标标签不得包含设备、IP、帧、异常文本、事件、追踪或其他高基数业务标识。

## 5. 部署与升级边界

Standalone 容器内监听 `0.0.0.0:9000`，宿主默认只绑定 `127.0.0.1:9000`。设备网开放前必须显式选择发布地址，完成防火墙来源白名单、
TLS、身份快照、容量参数和告警审批。明文只允许回环或受控内网开发；生产必须启用 TLS，且在原生 mTLS完成前由网络或外部终止层补齐
设备认证。

插件以 Gateway runtime 依赖进入 Spring Boot JAR，不支持运行时复制。协议键和 `protocolVersion` 不变时可滚动镜像；不兼容版本优先使用
新协议键和独立端口/部署并行迁移。若必须原端口切换，需要维护窗口同时替换镜像和完整身份快照。回退恢复上一不可变镜像及匹配快照，
未收到 ACK 的设备按原序号重传，不回滚数据库迁移或删除证据。

## 6. 生产启用前置门禁

以下项目全部完成并签字前，不得把本报告解释为生产上线批准：

- 取得真实厂商协议和脱敏正常、边界、异常、补传及命令样本，并由厂商确认 ACK 语义；
- 实现并验证原生 mTLS/设备证书身份、应用层登录挑战或经批准的等价认证；
- 使用真实 CA 完成证书签发、SAN、信任链、轮换、吊销、过期告警和密钥托管；
- 验证设备网 ACL、专线/APN、NAT、四层代理源地址、弱网、乱序、补传和退避重连；
- 以目标设备数、频率和帧分布验证连接、CPU、内存、文件句柄、RabbitMQ confirm、延迟与容量余量；
- 完成双 Gateway、负载均衡、滚动升级、协议并行迁移、网络分区、断电和恢复演练；
- 完成告警送达、值班响应、安全测试和 24/72 小时长稳。

# 系统配置、设备字段与命令管理设计

> 实施状态（2026-07-16）：菜单管理、通用字典、物模型字段、协议字段映射和低风险命令增强已经交付；中高风险命令审批、批量下发、样本解析测试和配置回滚仍属于后续阶段。当前页面不会暴露未完成的生产能力。

## 1. 目标

本次补齐三个彼此独立但可以协作的管理域：

1. 系统管理：菜单管理、字典管理和审计入口，解决新增菜单或通用选项必须修改 SQL、重启或重新发布的问题。
2. 设备定义：物模型字段与协议字段映射，解决不同厂商、不同报文字段无法统一展示和存储的问题。
3. 命令管理：命令模板、设备能力、动态参数、取消、原因、审批和弱网安全约束，解决一期只能下发 `QUERY_STATUS` 的限制。

三个域不能混成一套“万能配置表”。通用字典不负责协议解析，物模型字段不负责页面菜单，命令模板也不能允许管理员直接输入任意二进制。

## 2. 系统管理

### 2.1 菜单管理

菜单继续使用 `sys_menu`，新增完整 CRUD 与独立权限：

- `system:menu:view`
- `system:menu:create`
- `system:menu:update`
- `system:menu:delete`

管理字段包括父节点、名称、国际化键、类型、路由、组件标识、权限编码、图标、排序、可见性和状态。目录、页面、按钮采用不同校验：目录不配置组件，页面必须选择前端注册过的 `componentKey`，按钮必须配置权限且不生成路由。

菜单维护页使用树形表格，默认折叠按钮权限，并提供名称、节点类型、状态筛选以及展开/折叠全部。菜单树不使用普通分页，因为分页会拆散父子关系；未来节点达到数千级时改为服务端懒加载子树。创建和编辑表单的每个字段都必须提供国际化 Tooltip，说明适用节点类型、填写规则和示例。

前端组件仍使用静态白名单，后台不能把字符串拼成动态 import。后端提供组件目录接口，菜单页面只能从目录中选择。系统根节点和当前菜单管理节点标记为受保护节点，不允许删除；有子节点或仍被角色引用的节点不能删除。修改使用乐观锁并记录操作审计，成功后清理当前登录权限快照，用户刷新页面即可生效，不重启服务。

### 2.2 字典管理

新增：

- `sys_dict_type`：稳定类型编码、名称、状态、说明、审计字段和版本。
- `sys_dict_item`：类型 ID、值、中文标签、英文标签、语义颜色、排序、默认项、状态和版本。

字典用于车辆类型、班次类型、厂商类型等通用低频选项。已经被业务使用的类型编码和字典值不可原地修改，只能停用并新增。语义颜色仅允许 `default/primary/info/success/warning/error`，不能保存 CSS 类或颜色值。服务端按类型编码提供只读缓存，写入后精准失效；不启动定时刷新任务。

## 3. 设备字段与映射

### 3.1 物模型字段

按产品维护版本化物模型。本阶段使用以下两张核心表，避免在尚未出现多定义需求时过早增加空壳层级：

- `dev_model_version`：产品、版本号、草稿/已发布/已退役状态、说明、发布人与乐观锁版本。
- `dev_model_field`：属性标识、名称、数据类型、单位、读写模式、范围、精度和说明。

已发布版本不可修改。当前实现创建空草稿并原子保存字段；发布前校验属性标识唯一、数据类型和约束一致。同一产品只允许一个已发布版本，发布新版本会在同一事务内退役旧版本。

### 3.2 协议字段映射

协议解析字段和物模型字段通过版本化映射关联，不直接把厂商字段写进物模型：

- `dev_protocol_mapping_version`：按产品和 `profileKey` 区分厂商/型号/报文配置，支持 MQTT JSON、MQTT 二进制和 TCP 二进制。
- `dev_protocol_field_mapping`：保存源字段、源数据类型、目标物模型标识、转换类型和转换参数。

映射定义源字段、目标属性、缩放、偏移、受限表达式和必填策略。发布时强制目标字段全部存在于当前已发布物模型。运行时只能加载已发布配置，不读取正在编辑的草稿。样本报文测试、质量策略、内容哈希和一键回滚在下一阶段补齐。

## 4. 命令管理

### 4.1 页面结构

```text
命令管理
├── 命令中心        日常下发与最近结果
├── 命令记录        全量筛选、详情与导出
├── 命令模板        草稿、测试、发布、版本和设备能力绑定
└── 命令审批        中高风险待审批记录
```

### 4.2 命令模板

目标形态会新增 `cmd_template`、`cmd_template_version` 和 `cmd_template_binding`。模板版本包含参数 Schema、回复白名单、风险等级、默认 TTL、回复超时、离线排队策略、重试策略和协议编码器标识。绑定将模板版本关联到产品、物模型版本和配置发布。

当前阶段只开放代码内审查并发布的三个 LOW 模板：状态查询、设置遥测上报周期、请求定位。这样可以先验证动态表单、后端参数终验、回复白名单和弱网取消链路，同时避免管理员在审批能力完成前自行创建危险命令。

命令中心先选择设备，再根据设备当前生效配置查询可用模板。参数表单由受限 JSON Schema 生成，只支持对象、字符串、数字、整数、布尔和枚举，不执行模板中的脚本或 HTML。前后端都校验，后端校验是最终边界。

### 4.3 下发和安全

- 所有命令必须填写业务原因；可选关联工单号。
- LOW：二次确认后创建。
- MEDIUM：填写原因并由另一名具有审批权限的人员批准。
- HIGH：专用权限、双人复核、设备必须在线且数据新鲜，禁止离线排队和自动重试。
- 不提供任意文本、十六进制或 MQTT Topic 下发入口。
- 批量命令按设备分别创建实例，限制单批数量和发布速率，不共享 commandId。
- `CREATED/QUEUED` 状态允许取消；已发送后只能等待设备结果，不伪造取消成功。
- 写操作继续使用 `Idempotency-Key`，浏览器断网后不自动重放。

### 4.4 弱网交互

命令页面显示设备在线状态、最后遥测时间和数据新鲜度。离线设备是否可提交由模板决定；允许离线排队时必须展示绝对过期时间。状态通过既有命令状态消息推进，页面可以订阅实时状态；实时连接中断时保留最后状态并提示手动刷新。

## 5. 发布与运行时边界

菜单和字典属于系统管理配置，管理员保存后立即生效并记录审计。物模型、协议映射和命令模板属于生产配置，必须经过草稿、测试、影响预览、发布和回滚，不允许保存即运行。

平台启动不扫描这些表。写入成功后发送精确的本地/消息通知；服务重启只做一次有界加载。所有缓存有版本号和明确失效键，不以长 TTL 掩盖一致性问题。

## 6. 交付顺序

1. 菜单管理与字典管理。
2. 物模型字段与协议字段映射。
3. 命令模板、动态参数、原因、取消和记录页。
4. 中高风险审批、批量下发与在线联锁。

每一步都包含数据库迁移、中文表/字段注释、Sa-Token 权限、操作审计、OpenAPI、Vue 页面、国际化、单元/集成/E2E 测试；每一步完成后系统必须可独立部署运行。

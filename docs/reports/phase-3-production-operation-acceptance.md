## 3. 关键不变量

1. 班次、作业单、分配、候选和运营事实均属于组织与矿区；前端选择不能替代服务端数据范围。
2. 班次与作业单只能按显式状态机迁移；关闭班次前必须没有未终结作业和运行循环。
3. 发布作业单冻结路线、装载/卸载区域版本和调度显示快照，历史事实不随档案或空间版本变化漂移。
4. 自动识别只使用事件发生时有效的车辆/标签绑定、班次、作业状态历史和唯一分配。
5. 五步运输证据严格递增；重复事件幂等，过晚和已确定前沿之前的事件不能回滚状态。
6. 不能唯一、安全判断的事件必须形成候选或固定跳过，禁止默认选择第一张作业单或静默丢弃。
7. 原始执行事实和证据不可变；人工修正只追加并原子更新当前投影，作废记录不参与统计但仍可追溯。
8. 运营事实和 Outbox 同事务提交；实时发布失败只造成可见降级，不丢失数据库事实。
9. REST 固定业务水位与 WebSocket 连续业务序号共同保证可恢复读取；序号缺口必须回查。
10. 指标和告警禁止携带组织、矿区、作业单、车辆、司机、人员、事件标识和异常文本等高基数标签。

## 5. 数据库、消息和权限契约

管理 PostgreSQL：

- V43 创建班次、作业单、调度分配、运营事件队列、循环运行态、候选、执行事实、证据、修正、有效投影和可靠 Outbox。
- V44 创建持久动作幂等账本，发布“矿区管理 / 生产运营”菜单以及查看、班次编辑/关账、作业单编辑/调度、运营修正权限。
- V45 加固生命周期、发布快照、候选归属、事实/证据/修正和 Outbox 的约束、触发器与查询索引。
- V46 增加车辆和未解析标签的运营事件顺序索引，支撑发生时绑定和确定性认领。
- V47 创建作业单状态历史，以业务发生时间判定 `RUNNING/PAUSED`，避免用当前状态重写过去。
- V48 为每个矿区分配连续运营业务序号，保护 Outbox 水位分页和 WebSocket 缺口检测。
- V49 把已发布菜单迁移到前端固定组件白名单键 `mine-production-operations`。

所有新增表和字段均使用 `COMMENT ON TABLE/COLUMN` 提供中文注释；容器数据库集成测试校验注释完整性、外键/排斥/检查约束、不可变触发器、升级迁移、租约 fencing、幂等键和索引。

生产运营空间入口消费 `realtime.spatial.event.created` v1，自动或人工变更通过 `realtime.operation.updated` v1 发布。后者包含事件、组织、矿区、聚合类型/标识、固定更新类型、矿区连续业务序号、发生时间和有界摘要；前端只向具有 `mine:operation:view` 和目标矿区范围的 `MINE_SITE_OPERATION` 订阅分发。

## 6. API 与产品闭环

- 班次使用 `/shift-definitions` 和 `/shift-instances`，开启、关账、取消动作使用持久 `Idempotency-Key`。
- 作业单使用 `/work-orders`，分配单独追加；发布、启动、暂停、恢复、完成、取消和异常终止均为显式幂等动作。
- 候选使用 `/operation-candidates` 查询及 `/resolve` 关联、忽略或转人工补录。
- 执行记录使用 `/operation-records` 固定水位分页和详情追溯；补录与修正要求高风险权限、幂等键、原因和投影版本。
- 汇总使用 `/operation-summary`，最长查询 31 个营业日，不把未知吨位当作零或已校准实测。
- 前端 `/mine/operations` 统一承载概览、班次、作业单、候选和记录；实时增量只触发有界回查，连接失败时保留 REST 工作能力并明确显示降级。

精确请求/响应以 [Mine OpenAPI](../openapi/mine-api.yaml) 为准，操作与故障恢复见
[矿区生产运营运行手册](../runbooks/mine-production-operation-runtime.md)。

# 运行监控并发渐进检查实施计划

**目标：** 即时检查并发执行，检查结果在侧栏中逐项出现；Redis 即时检查通过真实连接探测返回准确状态。

**方案：** 后端增加单个检查项接口，复用既有超时和异常隔离逻辑。前端打开侧栏后立即建立全部检查项占位，并发调用单项接口，每个请求完成后独立更新对应行。Redis 使用 `RedisConnectionFactory` 执行 PING，避免响应式 Redis 健康贡献者无法从命令式 Actuator 注册表取到的问题。

## 实施任务

1. 为单项检查服务、控制器接口和 Redis PING 探针补充失败测试。
2. 实现 `GET /system/operations/items/{key}/check`，保持权限和响应结构与现有接口一致。
3. 实现 Redis 直接连接探针，覆盖正常、连接失败和资源关闭场景。
4. 前端改为并发调用单项接口，逐项显示检查中、完成状态和整体进度。
5. 更新 OpenAPI 契约及中英文国际化文案。
6. 执行后端测试、前端治理检查、类型检查、代码检查、单测和构建。

## 验收标准

- 点击“立即检查”后，全部检查项立即出现并显示各自检查中状态。
- 多个检查请求同时发出，先完成的项目先展示结果，不等待其他项目。
- Redis 已配置且可连接时即时检查显示正常，不再显示“当前部署未启用此检查”。
- 单项失败或超时不影响其他项目完成。
- 所有质量门禁通过。

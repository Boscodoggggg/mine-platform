# 遥测存储与选择性多级缓存设计

## 1. 目标

Task 8 将标准化遥测可靠地写入 TimescaleDB，并把设备最新值原子更新到 Redis。系统按 RabbitMQ 至少一次投递设计，必须保证重复消息、弱网补传、乱序数据以及“Redis 已更新但数据库写入失败”时不会重复产生历史数据，也不会用旧值覆盖新值。

本阶段不把设备最新值复制到 Java 进程内缓存。多台 `mine-telemetry` 和 `mine-server` 必须通过 Redis 看到同一份最新状态，避免节点间失效广播尚未完成时出现脏读。进程内缓存只预留给产品、物模型、协议、字段映射和策略配置等读多写少、按版本发布的数据。

## 2. 数据分层

| 层级 | 数据 | 作用 | 一致性策略 |
|---|---|---|---|
| L1 进程内缓存 | 产品、物模型、协议和策略的已发布版本 | 降低配置读取开销 | 有界容量、短 TTL、版本发布事件主动失效 |
| L2 Redis | 每台设备的最新属性值和排序游标 | 多实例共享实时读模型 | Lua 原子比较并更新，不采用固定统一过期时间 |
| L3 TimescaleDB | 遥测历史和消费幂等记录 | 可审计的历史事实 | 事务、业务唯一约束、批量写入 |

L1 在后续配置发布任务中实现，本阶段只定义边界，不引入 Caffeine 依赖。历史范围查询不进入通用缓存，避免大结果集挤占实时数据空间。

## 3. 写入与确认顺序

一批 RabbitMQ 消息解析成按属性展开的数值遥测点。消费者先通过 Redis Lua 脚本尝试更新最新值，再在单个 TimescaleDB 事务中占用 Inbox 幂等键并批量写历史。只有两侧操作都成功后才手工 ACK；任一步失败都 NACK 并重新入队。

Redis 先成功、TimescaleDB 后失败时，消息重投会再次执行 Lua。相同或更旧的排序游标被拒绝，因此不会回退最新值；数据库事务失败时 Inbox 占位同步回滚，重试仍可正常写入历史。TimescaleDB 的 `event_id` 主键和 `(device_id, boot_id, sequence, message_type)` 部分唯一约束共同防止消息重投和厂商更换 messageId 后的业务重复。

Redis 最新值使用设备级 Hash，属性是 Hash field，避免把全矿区设备集中到单个热点 key。排序游标由有效时间和稳定决胜信息构成，Lua 在 Redis 内完成比较与写入，禁止 Java 侧“先读后写”。

## 4. 穿透、击穿与雪崩

- 缓存穿透：写入链路只接受已通过 gateway 身份映射的内部 UUID；查询链路先校验设备和物模型属性。不存在的配置可使用带随机抖动的短 TTL 空值缓存。
- 缓存击穿：Task 9 的 Redis miss 回源按 `deviceId + propertyId` 做 single-flight；一个请求查询 TimescaleDB，其余等待有限时间或返回允许的旧值。
- 缓存雪崩：活动设备 latest Hash 不设置统一固定 TTL，由设备归档流程清理；需要 TTL 的配置、空值和会话加入随机抖动。Redis 恢复后的回源重建必须限并发、分批执行。
- 热点保护：设备级 Hash 拆分 key；批量查询设上限；禁止 `KEYS *`、全矿区一次性回填和无界本地缓存。
- 降级边界：Redis 不是真相源。Redis 故障期间历史仍可写入，但消息保持未确认，待 Redis 恢复后重投；后续可增加“仅历史降级”开关，但必须显式告警并记录待重建范围。

## 5. 设备标识与部署

TimescaleDB 使用平台内部 UUID 作为 `device_id`。gateway 身份快照必须同时携带内部 `deviceId` 和厂商报文中的 `deviceCode`：报文校验使用 `deviceCode`，统一消息输出内部 UUID 字符串。禁止把矿区自然编码直接写入 UUID 列。

`mine-telemetry` 使用独立 RabbitMQ 只读账号、TimescaleDB 账号和 Redis 密码。单机 Compose 与多机部署均使用相同逻辑组件边界；Redis 高可用差异只体现在连接地址和 Sentinel 配置，不改变缓存接口。

## 6. 验收条件

- 正常遥测产生一组历史属性行并更新 Redis 最新值。
- 相同 eventId 或相同可靠业务幂等键只写一次历史。
- Redis 成功、TimescaleDB 失败后重投可恢复，最新值不回退且历史不重复。
- 迟到、乱序或旧 boot 数据可以保存历史，但不得覆盖 Redis 最新值。
- RabbitMQ 仅在持久化成功后 ACK，失败批次重新投递。
- 新增 Inbox 表及全部字段具有中文数据库注释，并由真实 TimescaleDB 测试校验。

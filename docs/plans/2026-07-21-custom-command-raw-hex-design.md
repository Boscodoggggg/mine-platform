# 自定义命令与 MQTT 十六进制下发设计

## 1. 背景与目标

当前命令中心只能使用代码内固化的 `QUERY_STATUS`、`SET_REPORT_INTERVAL` 和 `REQUEST_LOCATION` 三个低风险模板。系统缺少命令模板草稿、版本发布、产品绑定和管理员临时原始字节下发能力。

本次交付第一版自定义命令控制面，目标是：

- 管理员可以创建绑定产品的低风险命令模板。
- 模板支持现有 MQTT JSON 命令和固定 MQTT 原始十六进制载荷。
- 具备独立高权限的管理员可以在命令中心临时输入十六进制载荷。
- 所有载荷在进入可靠 Outbox 前完成后端校验并固化执行快照。
- 原始十六进制命令只确认发布到设备侧 Broker，不宣称设备已经执行成功。

第一版不支持 TCP 原始字节、任意 MQTT Topic、中高风险审批、批量下发、脚本模板和设备回复解析。

## 2. 安全边界

模板管理和临时原始载荷是两个权限边界：

- `command:template:view`：查看模板。
- `command:template:edit`：创建模板草稿和保存草稿版本。
- `command:template:publish`：发布模板版本。
- `command:raw:execute`：临时输入并下发原始十六进制载荷。

临时原始载荷必须同时满足：

- 目标设备启用并采用 MQTT 接入模式。
- 设备接入状态为 `ONLINE`。
- 下发原因非空。
- 十六进制规范化后非空、字节数不超过 4096、字符合法且长度为偶数。
- 前端展示设备、字节数和标准化载荷后二次确认。

MQTT Topic 继续由设备可信身份生成。模板和临时下发都不能输入或覆盖 Topic。

## 3. 数据模型

V59 新增三张表：

- `cmd_template`：稳定模板编码、生命周期状态和乐观锁版本。
- `cmd_template_version`：不可变版本、草稿/已发布/已退役状态、载荷格式、参数 Schema、固定原始字节、TTL、超时和发布审计字段。
- `cmd_template_binding`：把模板版本绑定到产品。

`cmd_instance` 增加：

- `dispatch_source`：`BUILTIN_TEMPLATE`、`CUSTOM_TEMPLATE` 或 `AD_HOC_HEX`。
- `payload_format`：`MQTT_JSON` 或 `RAW_HEX`。
- `raw_payload`：实际下发的原始字节快照。
- `raw_payload_hex`：原始字节的大写十六进制展示快照。
- `payload_sha256`：原始字节摘要。
- `reply_expected`：是否等待设备业务回复。

临时十六进制实例使用保留模板编码 `RAW_HEX_AD_HOC`。历史实例不依赖模板表存活；模板停用或产生新版本不会改变已创建实例的载荷。

所有新增表和字段提供中文数据库注释，数据库集成测试校验注释完整。

## 4. 模板生命周期

创建模板时同时创建版本 1 草稿。草稿可保存名称、产品绑定、载荷格式和载荷定义：

- `MQTT_JSON`：第一版使用平台现有 `command + parameters` 信封，参数 Schema 使用受限 JSON Schema。
- `RAW_HEX`：保存固定字节，不允许执行时覆盖；参数 Schema 必须为空对象。

发布时执行后端最终校验。一个模板同时只能存在一个已发布版本；发布新版本会退役旧版本。已发布版本不可修改，修改必须复制为下一个草稿版本。第一版只允许 `LOW` 风险。

查询可下发模板时必须传入设备标识，后端按设备所属产品返回已发布绑定，同时兼容返回三个内置 JSON 模板。

## 5. 命令执行与消息契约

`CommandDispatchPayload` 增加 `payloadFormat`、`rawPayloadBase64` 和 `replyExpected`。新增字段保持向后兼容：旧 JSON 消息缺少字段时按 `MQTT_JSON` 和需要回复处理。

网关发布逻辑：

- `MQTT_JSON`：保持现有 JSON 编码、`application/json` 和设备 ACK 超时调度。
- `RAW_HEX`：Base64 解码后原样发布、使用 `application/octet-stream`，禁止空载荷和超过 4096 字节。

Broker confirm 成功后：

- 需要回复的命令发布 `SENT` 并创建一次性超时消息。
- 无需回复的 RAW_HEX 命令发布新增终态 `PUBLISHED`，不创建超时消息。

`PUBLISHED` 表示设备侧 Broker 已确认接收消息，不表示设备已经执行。

## 6. 前端交互

命令管理目录新增“命令模板”页面：

- 展示模板编码、名称、产品、版本、状态和载荷格式。
- 创建和编辑草稿。
- RAW_HEX 编辑器接受空格、换行和可选 `0x` 前缀，实时展示标准化内容和字节数。
- 发布前展示不可变版本确认。

命令中心新增“原始十六进制”高级入口，仅对 `command:raw:execute` 权限可见。表单包含设备、十六进制载荷和必填原因。确认框明确提示“仅确认发布，不代表设备执行成功”。

命令列表和详情新增来源、载荷格式、载荷摘要，并支持 `PUBLISHED` 状态国际化展示。

## 7. 错误处理与审计

业务错误覆盖模板不存在、草稿状态错误、版本冲突、产品未绑定、非法 Schema、非法十六进制、载荷过大、设备非 MQTT、设备不在线和未发布模板。

模板创建、草稿保存、发布、模板下发和临时十六进制下发都写入操作审计。审计记录保存载荷格式、字节数和 SHA-256；完整原始载荷保存在受现有命令查看权限保护的命令实例中，避免复制到多份日志。

## 3. 关键不变量

1. 设备载荷不能决定可信设备、矿区、资产对象或统一坐标；这些身份来自凭据快照和定位运行快照。
2. 历史事实只按设备 `occurredAt` 解析当时生效的绑定与坐标转换，不按当前主数据回写。
3. 重复 `(sourceDeviceId, bootId, sequence)` 不产生第二条历史或实时副作用；迟到事实不得让当前位置倒退。
4. 低质量点可保留历史，但不覆盖较新的优质当前位置；未知、归档、未授权、非有限和越界观测进入有界隔离。
5. 位置事实和实时 Outbox 在同一数据库事务提交；Redis 失败不能回滚历史，也不能丢失可靠实时发布证据。
6. 快照整包验证通过后才切换，失败时继续使用最后正确修订；快照和人员敏感字段严格分离。
7. REST、WebSocket 和前端矿区选择均不能替代后端数据范围校验。
8. 指标和告警不携带组织、矿区、设备、标签、车辆、人员、坐标系或异常文本等高基数标签。

## 5. 数据库与消息契约

管理 PostgreSQL V33～V38 建立组织/矿区/授权、资产/坐标、人员/资质、时间绑定、换绑操作、定位运行快照和矿区导航。
TimescaleDB V21～V24 将位置表升级为双坐标事实，并建立运行修订、Inbox、隔离区、实时 Outbox、缓存恢复水位和查询索引。
所有新增表和字段都有中文注释，集成测试验证表/字段注释完整性、约束、不可变性和升级行为。

外部定位主题固定为：

```text
mine/v1/{productKey}/{clientId}/up/location
```

Gateway 只接受固定 JSON v1 字段；内部观测固定为 `location.observation`，实时白名单事件固定为
`realtime.location.updated` v1。浏览器定位订阅需要 `mine:location:view` 和目标矿区数据范围。

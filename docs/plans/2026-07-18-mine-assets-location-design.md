# 矿区资产、时间绑定与模拟定位纵向闭环设计

## 1. 目标与边界

本切片进入 Phase 3“智慧矿山业务”，把现有设备接入、遥测、告警和命令能力关联到真实业务语义：哪个集团、哪个矿区、哪辆车、哪个司机、哪个定位标签，以及定位发生时这些对象之间是什么关系。一级菜单固定为“矿区管理”，首批交付矿区档案、车辆管理、人员管理、定位标签、绑定管理和实时定位，为后续路线围栏、班次、作业单和运营统计提供稳定基础。

本切片采用“集团组织—矿区”双层模型，面向单客户独立部署但原生支持多个矿区。它不是完整 SaaS：不建设租户注册、计费、套餐、独立域名和跨客户运维控制面；同时不采用单矿隐式模型，避免后续为集团驾驶舱和跨矿授权重构全部业务表。

定位使用厂商无关模拟数据完成纵向链路。首批不声明兼容任何真实 UWB 厂商协议，不替代现场坐标标定、定位精度、容量、HA 或长稳验收。路线、围栏和作业闭环继续作为后续切片，但本次实体、事件和位置事实不能阻断它们的实现。

## 2. 领域模型与作用域

`Organization` 表示客户集团或矿业公司，`MineSite` 表示具体矿区。车辆、定位标签、坐标系和定位事实属于单一矿区；人员属于集团，通过 `PersonSiteAssignment` 获得带时间的矿区任职关系。用户操作权限继续由现有 RBAC 控制，数据可见范围由独立的组织/矿区授权控制，服务端不能信任前端传入的 `organizationId` 或 `siteId`。

首批核心对象：

| 对象 | 核心职责 |
|---|---|
| `Organization` | 集团编码、名称、状态和归档生命周期 |
| `MineSite` | 矿区编码、名称、时区、状态和所属集团 |
| `Vehicle` | 车辆编码、类型、矿区编号、品牌型号、额定载荷和生命周期 |
| `Person` | 集团级人员档案和脱敏联系方式 |
| `PersonSiteAssignment` | 人员在矿区的带时间任职关系 |
| `DriverQualification` | 资质类型、证件掩码/密文、允许车型、有效期和状态 |
| `LocationTag` | UWB/定位标签编码、厂商型号、电量和资产状态 |
| `CoordinateSystem` | 原始或统一坐标系、坐标类型、单位和矿区归属 |
| `CoordinateTransformVersion` | 不可变转换算法、参数、有效期和版本摘要 |

车辆、人员、标签和矿区采用归档，不物理删除已被绑定、定位、作业、告警或审计引用的数据。人员联系方式默认脱敏；证件号加密保存，只向独立敏感权限返回掩码之外的受控内容，并记录访问审计。

## 3. 时间绑定与历史不变量

首批提供四类独立绑定：`VehicleDeviceBinding`、`VehicleTagBinding`、`PersonTagBinding` 和 `PersonVehicleBinding`。不用一个多态表保存任意对象关系，避免数据库外键、排斥约束和查询计划失去确定性。

全部绑定使用 `[validFrom, validTo)` 半开时间区间，并遵守：

1. 同一定位标签同一时刻只能绑定一个可定位对象；车辆标签和人员标签之间也不能交叉重叠。
2. 同类主设备同一时刻只能有一个主绑定，一个物理设备不能同时属于两个矿区或两辆车辆。
3. 一个司机不能在重叠时间驾驶多辆车，一辆车也不能同时分配多个主司机。
4. 新绑定不能覆盖旧记录；换绑必须在同一事务中关闭旧关系、建立新关系、写操作审计并产生业务事件。
5. 绑定的组织、矿区、对象状态和司机资质必须在服务端校验，跨矿绑定直接拒绝。

PostgreSQL 使用 `tstzrange`、`btree_gist` 和 GiST 排斥约束兜底并发写入，应用服务在写入前提供可理解的冲突对象和时间范围。绑定若需要追溯修正，必须走带原因、影响预览和位置重放的专门流程；首版只允许当前或未来换绑，不允许静默修改已形成定位事实的历史区间。

## 4. 双坐标与定位事实

每个定位点同时保存厂商原始坐标和转换后的矿区统一坐标，不能只保存转换结果。原始坐标记录坐标系、坐标类型、`x/y/z` 或经纬高语义、单位和设备质量；统一坐标固定为矿区米制 `x/y/z`，记录目标坐标系和不可变转换版本。

转换通过稳定适配器选择算法。首批支持本地坐标恒等转换、版本化三维仿射转换和 WGS84 到矿区局部 ENU 的转换；算法参数在发布后不可原地修改，只能创建新版本和有效期。位置事实还保存集团、矿区、来源设备、标签、发生时绑定、车辆或人员、`occurredAt`、`receivedAt`、精度、质量、稳定事件 ID、`bootId` 和 `sequence`。

历史位置写入 TimescaleDB hypertable。绑定解析以 `occurredAt` 为准，并把实际 `bindingId` 与业务对象 ID 固化到事实，后续换绑不改变旧轨迹。已注册但未绑定的标签可以保存标签级历史，不冒充车辆或人员位置。重复消息由事件 ID 和设备周期序号幂等；乱序点保存历史，但不能倒退当前位置。

当前位置在历史事实成功提交后写入 Redis，并可由 TimescaleDB 最新事实重建。质量为 `VALID` 的新点可以推进当前位置；`DEGRADED` 点保留历史和原因，但不能覆盖更新且更可靠的位置；`REJECTED` 点不形成位置事实，只保存有界隔离证据并进入死信。

## 5. 消息链路与运行快照

模拟定位不能调用管理 API 直接改当前位置。设备模拟器以受控设备身份发送厂商无关定位观测，Gateway 完成来源身份和协议边界校验后发布稳定 `LocationObservation`：

```text
模拟定位设备
→ Gateway 身份与协议校验
→ RabbitMQ 定位观测
→ Telemetry 幂等、坐标转换和发生时绑定解析
→ TimescaleDB 位置事实
→ Redis 当前位置
→ RabbitMQ/WebSocket 实时更新
```

Server 将矿区、标签、坐标转换版本和时间绑定发布为分页、带修订与摘要的完整运行快照。Telemetry 暂存并校验完整快照后原子激活；低修订、同修订异内容、分页缺失和损坏快照都不能覆盖最后正确值。定位热路径不逐点同步调用 Server。

质量分为 `VALID`、`DEGRADED` 和 `REJECTED`。未知或归档标签、来源设备越权、坐标非有限值、越界、转换缺失和版本冲突使用固定低基数原因码。日志和指标不得把人员姓名、标签编码、设备 ID、坐标或原始载荷放入 label；隔离证据保存摘要、作用域、时间和固定原因，不无限保存原始报文。

模拟器提供正常轨迹、低质量、重复、乱序、未绑定标签和越界坐标场景，全部显式标记为模拟数据。

## 6. API、菜单与前端体验

动态菜单新增一级目录“矿区管理”：

```text
矿区管理
├── 矿区档案
├── 车辆管理
├── 人员管理
├── 定位标签
├── 绑定管理
├── 实时定位
├── 路线围栏（后续）
└── 作业管理（后续）
```

现有“设备管理”继续管理产品、物模型、物理设备、凭据、连接和策略；“矿区管理”解释设备在生产中的业务归属。设备详情可以跳转绑定车辆，车辆详情可以跳转物理设备，但权限分别校验。

绑定不提供无约束 CRUD。换绑前展示旧关系、目标对象、切换时刻、资质状态和影响范围，确认后原子执行。实时定位使用不依赖公网瓦片的二维矿区坐标画布，展示车辆/人员标记、位置质量、数据新鲜度、轨迹和详情侧栏。轨迹 API 强制时间窗、最大点数和服务端抽稀，禁止浏览器加载无界点集。

权限至少分为矿区档案、车辆、人员、敏感人员字段、资质、标签、绑定切换和定位查看。用户拥有页面权限仍只能访问显式授权的集团/矿区。全部用户可见文案进入中英文资源；业务页面遵守 Naive UI、UnoCSS、统一主题和 UI 治理规则。

## 7. 测试与验收

自动化门禁至少证明：

1. 集团和矿区作用域隔离，同编码业务对象不冲突且不能越权读取。
2. 标签、主设备和司机的重叠绑定在服务与数据库两层拒绝，并发写入不能绕过。
3. 历史位置按发生时关系关联，换绑不改变旧轨迹。
4. 原始坐标、统一坐标、转换版本和质量证据完整且不可静默覆盖。
5. 重复、乱序、低质量、未绑定、越界和转换失败场景符合固定语义。
6. Redis 故障不丢历史，恢复后可以重建当前位置。
7. 敏感字段脱敏、授权、审计和归档保护有效。
8. 动态菜单、按钮权限、矿区数据作用域、中英文、主题和响应式布局通过治理。
9. 模拟器能够完整演示车辆、司机、标签绑定和移动轨迹。

集成测试使用真实 PostgreSQL、TimescaleDB、RabbitMQ 和 Redis Testcontainers，不用 H2 或内存假 MQ证明生产集成。验收报告必须把仓库自动化与现场资格分开：真实 UWB 厂商协议、现场坐标标定、定位误差、目标设备频率、容量、HA、备份恢复和 24/72 小时长稳仍是生产阻断项。

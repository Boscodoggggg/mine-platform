# 00 产品范围与工程原则

## 1. 产品定位

平台服务于单个智慧矿山的本地生产环境，接收矿车、UWB 标签、车载终端、传感器和第三方控制器的数据，完成接入、解析、标准化、存储、告警、实时展示、业务关联和命令下发。

它首先是生产数据基础设施，其次才是管理后台。任何页面功能都不能以破坏采集稳定性、消息可追踪性或数据可恢复性为代价。

## 2. 目标用户

| 用户 | 主要工作 |
|---|---|
| 系统管理员 | 用户、角色、菜单、参数、审计和部署状态 |
| 设备接入工程师 | 产品、设备、凭据、协议、样本调试和字段映射 |
| 矿山调度人员 | 实时监控、车辆、人员、路线、告警和命令 |
| 运维工程师 | 服务状态、积压、日志、备份、升级和故障恢复 |
| 数据分析人员 | 历史曲线、运营记录、统计和数据导出 |
| 协议插件开发者 | 实现配置引擎无法表达的复杂厂商协议 |

一期只预置超级管理员。其他角色由管理员在前台自行创建并授权，不把矿区组织结构硬编码进系统。

## 3. 一期必须实现

### 3.1 平台底座

- 本地用户、Sa-Token 登录、菜单按钮权限和操作审计。
- 产品、设备、设备分组、凭据、在线状态和生命周期管理。
- 单机 Compose、五节点 Compose、监控、日志、备份和离线安装。

### 3.2 数据接入

- RabbitMQ MQTT Broker 随平台部署。
- MQTT 3.1.1/5.0 设备接入和私有 TCP 二进制接入。
- 粘包拆包、CRC、大小端、定长、变长、分隔符、TLV、JSON 等常见解析。
- 弱网重复、乱序、迟到、断线重连和补传。

### 3.3 可配置能力

- 物模型、协议、字段映射、显示元数据、告警、保留、数据质量和命令模板。
- 草稿、样本测试、影响预览、管理员直接发布、热加载和回滚。
- 产品默认、设备组、设备覆盖三级继承。

### 3.4 矿山业务

- 车辆、人员/司机、设备绑定、UWB 标签绑定。
- 路线、途径点、围栏、班次、作业记录和运营统计。
- 实时监控、历史查询、告警事件、命令下发与回复。
- 可选三维场景，展示车辆、人员、轨迹、告警和围栏。

## 4. 明确不做

- 不开发 CAD/BIM/三维建模工具，不自动生成精细矿山模型。
- 不建设传统多租户 SaaS，不按租户拆库或计费。
- 不在一期引入 Kubernetes、Nacos、Kafka、服务网格和全链路追踪平台。
- 不允许在前台执行任意 Groovy、JavaScript、SpEL 或 SQL。
- 不承诺任意未知厂商协议都能零代码接入。
- 不把 Redis 当历史数据真相，不把 RabbitMQ 当永久数据仓库。
- 不承诺端到端 exactly-once；采用 at-least-once 加业务幂等。
- 不把所有 Java 模块拆成独立微服务。

## 5. 规模基线

- 设备规模：5000 台以上，保留扩容余量。
- UWB：可能存在高频位置点，必须使用独立表、批写和专门压测模型。
- 网络：允许高延迟、抖动、丢包、重复、乱序和分钟级中断。
- 部署：矿区本地私有网络，可完全离线安装和运行。
- 可用性：五节点为推荐生产基线；单机可生产但明确无主机级容灾。

“5000 台”不是唯一容量指标。压测模型必须同时描述连接数、每秒消息数、平均/最大报文、QoS、订阅数、UWB 频率、WebSocket 用户数和保留周期。

## 6. 工程原则

### 6.1 纵向闭环优先

先用一种真实设备完成上报、解析、存储、展示和命令闭环，再扩展通用平台。禁止先造半年抽象框架而没有可运行链路。

### 6.2 配置优先，插件兜底

可声明的协议和策略使用结构化配置；复杂逻辑使用受控 Java SPI。配置能力不以“无限灵活”为目标，而以可校验、可编译、可测试和可回滚为目标。

### 6.3 运行时快照

发布后的配置编译成不可变快照。运行节点只消费完整、经过校验的快照，不在消息热路径逐条读取数据库或解释原始 JSON。

### 6.4 历史可追溯

设备绑定、策略发布、命令、告警和运营记录不能通过覆盖旧值破坏历史。发布版本不可原地修改，绑定关系带生效时间和失效时间。

### 6.5 控制面与数据面分离

后台配置和管理属于控制面；设备连接、消息解析和遥测入库属于数据面。控制面短时故障不能导致已加载的数据面配置失效。

### 6.6 可观测与可恢复

每个异步链路必须有 messageId、时间戳、来源和处理结果。每个有状态组件必须定义备份、恢复、告警和容量上限。

## 7. 成功标准

一期成功不是“页面都能点”，而是同时满足：

- 新增一个常规协议可以通过页面配置、样本测试并发布。
- 设备断网后补传不会覆盖更新的当前值，也不会重复产生业务事件。
- 命令能区分已入队、已发送、设备收到、执行成功、拒绝、失败和超时。
- 单机和五节点都能使用离线包安装、升级、回滚和恢复。
- 5000 客户端、重连风暴、UWB 高频、队列积压和 72 小时稳定性测试通过。
- 现场运维人员能够依据手册完成巡检、备份恢复和故障处置。

## 3. 关键不变量

1. 空间对象属于组织和矿区；客户端 `siteId`、坐标或标签身份不能替代服务端数据范围和运行快照。
2. 发布版本及其路线引用、围栏顶点不可原地修改；事件必须引用当时不可变区域版本和 `sha256:` 内容摘要。
3. 只有完整空间快照通过数量、摘要和几何校验后才激活；失败时继续使用最后正确修订。
4. 位置按 `occurredAt`、摄入序号和已发布迟到策略确定顺序；过晚事实不回滚已经确定的区域状态。
5. `BOUNDARY` 保持稳定状态，进出需要连续确认点，单次进入周期最多形成一次 `DWELL`，低质量点不得驱动高风险转换。
6. 区域状态、空间事件和 Outbox 在同一事务提交；业务唯一键和 Inbox/租约防止重试形成重复副作用。
7. 重放冻结当前活动区域版本、源水位和数据库快照，使用独立状态，不能覆盖在线状态或随批次扩大输入集合。
8. REST 固定水位和 WebSocket 缺口重同步保证可恢复读取；空间事件实时失败不应拖垮基础定位。
9. 指标和告警禁止携带组织、矿区、区域、标签、车辆、人员、事件标识和异常文本等高基数标签。

- V41 扩展 `WAYPOINT_VERSION/ROUTE_VERSION/GEOFENCE_VERSION` 快照条目和 `SPATIAL_CHANGE` 原因，并保护坐标系与空间版本引用。

TimescaleDB：

- V25 创建评估队列、水位、在线状态、空间事件、事件 Outbox 和重放请求。
- V26 增加租约令牌并创建空间运行快照及条目，防止旧执行器越权完成新租约。
- V27 增加事件查询序号水位、重放独立状态和最小权限活动区域快照视图，冻结重放源水位与游标。
- V28 增加空间事件 Outbox `DEAD` 状态的部分索引，避免死信指标全表扫描。

所有新增表和字段均使用 `COMMENT ON TABLE/COLUMN` 提供中文注释，管理库与时序库集成测试校验注释完整性、约束、索引、
不可变性、升级迁移、租约 fencing、固定水位和最小权限。

可靠实时消息固定为 `realtime.spatial.event.created` schema v1，包含事件/组织/矿区、稳定区域及不可变版本、发生时标签与车辆或人员、
状态转换、锚点位置事实、确认点数、摄入序号、运行修订、发生时间和有界判定证据。Telemetry 通过 `realtime.spatial.*` 路由发布，
mine-server 消费后只向具有 `mine:spatial:event:view` 和目标矿区范围的 `MINE_SITE_SPATIAL_EVENT` 订阅分发。

## 6. API 与产品闭环

- 主数据使用 `/api/v1/mine/sites/{siteId}/waypoints|routes|geofences` 的稳定对象、版本、发布和归档接口。
- 当前生效区域使用 `/spatial-regions/current`；列表每页最多 100 条且状态枚举固定。
- 事件使用 `/spatial-events` 和 `/spatial-events/{eventId}`，默认 24 小时、最长 31 天、每页最多 200 条。
- 重放使用 `/spatial-events/replays`，要求独立权限、稳定 `Idempotency-Key`、原因和不超过 31 天的半开窗口，只返回 HTTP 202。
- 前端“矿区管理 / 路线与围栏”统一承载主数据、版本发布、事件查询/详情、实时增量和重放登记；实时定位页叠加当前区域和事件。

精确请求/响应以 [Mine OpenAPI](../openapi/mine-api.yaml) 为准，数据库和消息说明见
[接口、消息与数据库基线](../11-contracts-and-database.md)。

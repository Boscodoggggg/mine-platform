# 数据保留独立导航设计

## 目标与选择

数据保留已经具备策略编辑、影响预览、不可逆发布确认和执行事实查询，但仅作为“策略工作台”的一个类型出现，可发现性不足。独立导航采用“数据治理 → 数据保留”两级信息架构，保留原“设备管理 → 策略工作台”入口，兼顾治理人员的专属工作流和现有客户的操作习惯。

对比过三种方案：只给策略工作台加角标成本最低但仍难发现；直接在设备管理下增加同级菜单路径最短，但无法承载后续数据质量、生命周期和合规能力；新增数据治理域更符合可售产品的长期信息架构。因此选择第三种，同时首版只发布“数据保留”一个子菜单，不提前建设未落地模块。

## 架构与数据流

后端通过 V28 Flyway 迁移新增受保护的“数据治理”目录和“数据保留”菜单。菜单使用独立导航权限 `governance:retention:view`，并把已经拥有 `device:strategy:view` 的角色无损映射到新入口，同时补齐产品查看和设备查看依赖。日常角色授权中，服务端会在选择数据保留入口时原子补齐产品查看、设备查看和策略查看三个最小依赖，避免可见但不可用的死入口；角色权限树采用精确节点选择，不把只读父菜单级联扩张为创建、归档、凭据、编辑或发布权限。底层编辑、发布权限保持不变，超级管理员仍按现有机制读取全部启用菜单。

前端新增 `retention-governance` 组件白名单键和 `/governance/retention` 动态路由。专属页面只是一个薄入口，向现有策略工作台传入固定类型 `RETENTION`；核心编辑、预览、发布、错误处理和执行事实继续只有一份实现。固定模式隐藏策略类型选择器，使用数据治理专属标题和说明，产品、范围、权限和所有后端请求协议保持不变。

## 失败处理与验证

数据库迁移测试校验目录、菜单、可用读取权限、角色继承、UUIDv7 关联主键和幂等迁移；动态路由测试校验组件白名单与中英文菜单；组件测试校验专属页面固定为保留策略、不允许切换，并在没有活动产品或产品查询失败时仍独立加载全局执行事实；Playwright 从新菜单进入，验证预览和发布前确认仍可使用。真实设备、现场网络、负载与高可用验证继续按照当前约定延期，不作为本次导航升级的完成条件。

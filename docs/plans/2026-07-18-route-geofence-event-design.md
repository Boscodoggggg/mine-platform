# 路线、途径点与电子围栏事件闭环设计

## 1. 目标与边界

本切片承接 Phase 3 已完成的双坐标定位纵向闭环，为后续班次、作业单和运营记录提供稳定空间语义。交付范围包括：

- 矿区统一坐标系下的版本化途径点、路线和多边形电子围栏；
- 草稿编辑、严格校验、不可变发布、有效时间和历史版本查询；
- 途径点圆形区域与电子围栏多边形区域的进入、离开、持续停留事件；
- 迟到容忍、边界抖动消除、低质量点隔离、状态恢复和历史重放幂等；
- 事件查询、可靠实时发布、前端管理与运行事件工作台；
- 低基数指标、告警、自动化模拟、运行手册和仓库验收证据。

首版不实现道路吸附、复杂缓冲区、多多边形/洞、三维网格、PostGIS 在线空间查询或独立流处理集群。高度只使用可选
`minZ/maxZ` 区间；二维多边形顶点和圆形途径点均必须落在矿区唯一活动统一坐标系边界内。真实道路测绘、围栏边界复核、
现场定位误差、峰值容量、HA 和长稳继续标记为 `DEFERRED`。

## 2. 方案选择

采用“管理 PostgreSQL 控制面 + 不可变运行快照 + Telemetry 本地判定与持久状态”方案。

管理库负责低频配置、作用域、版本、审计和发布。定位运行快照新增 `WAYPOINT_VERSION`、`ROUTE_VERSION`、
`GEOFENCE_VERSION` 条目，Telemetry 延续整包暂存、摘要校验、原子激活和 last-known-good。高频位置点不逐条调用
mine-server，也不逐点执行管理库或 PostGIS 查询。

没有选择 PostgreSQL/PostGIS 每点查询，因为它会让高频热路径依赖远程空间 SQL，并把数据库连接数和索引调优变成定位
可靠性的前置条件。没有选择 Flink 等独立流处理集群，因为当前部署需要保持单机 Compose 可运行，新增集群会显著提高交付、
恢复和客户运维成本。运行快照和 `SpatialEvaluator` 接口保留了以后替换空间索引或下沉流处理的边界。

## 3. 控制面模型

途径点、路线和围栏均分成稳定对象表与版本表：

- `mine_waypoint` / `mine_waypoint_version`：稳定编码；版本保存名称、类型、圆心、半径、高度、消抖和停留参数；
- `mine_route` / `mine_route_version` / `mine_route_version_waypoint`：稳定编码；版本保存方向、适用车辆类型、有效时间和有序途径点；
- `mine_geofence` / `mine_geofence_version` / `mine_geofence_vertex`：稳定编码；版本保存类型、有效时间、高度、边界容差、消抖、停留和有序顶点。

稳定对象只允许活动或归档。版本状态只允许 `DRAFT`、`PUBLISHED`；草稿使用乐观锁修改，发布时计算规范化 SHA-256 摘要，
发布后的版本、路径点和顶点禁止更新或删除。同一稳定对象的已发布有效区间使用 GiST 排斥约束禁止重叠。路线发布必须引用
同矿区、同统一坐标系、已发布且有效期覆盖路线有效期的途径点版本。多边形至少三个不重复顶点、无自相交、面积大于最小阈值，
首尾由算法隐式闭合，禁止重复末端顶点。

所有表和字段使用 `COMMENT ON TABLE/COLUMN` 提供中文注释；集成测试遍历 `information_schema.columns` 和
`col_description` 校验完整性。所有业务查询同时使用组织和矿区条件，前端 `siteId` 不能替代服务端数据范围授权。

## 4. 空间判定与迟到容忍

定位事实提交后只把优质、已绑定或标签级的统一坐标事实加入 `spatial_evaluation_queue`。每个标签维护最大事件时间水位，正常
情况下只处理 `occurredAt <= maxOccurredAt - allowedLateness` 的点；流量停止超过空闲刷新时间后，按发生时间和
`ingestSequence` 排空剩余点。这样在容忍窗口内到达的乱序点会先排序再判定，超过窗口的点保留历史但记录 `TOO_LATE`，不回滚
已经发出的空间事件。

多边形使用确定性的射线法，先计算点到边线段距离。距离小于 `boundaryToleranceMeters` 的点分类为 `BOUNDARY`，保持上一稳定
状态且不累加候选计数。途径点使用圆心距离和同样的边界容差。可选高度区间在二维分类后判定；没有 Z 的位置不能触发带高度限制
的区域事件。

每个区域和标签维护 `stableState`、`candidateState`、`candidateCount`、`enteredAt`、`dwellEmittedAt`、最后位置事件和水位。
只有连续满足 `enterConfirmPoints` 或 `exitConfirmPoints` 才切换稳定状态。进入后累计事件时间达到 `dwellSeconds` 只发送一次
`DWELL`；离开后清除本次停留证据。`DEGRADED`、边界、过晚和缺少高度的点均有固定跳过原因，不参与危险业务判定。

## 5. 幂等、重放与可靠发布

空间状态更新、`spatial_event` 和 `spatial_event_outbox` 在同一 TimescaleDB/PostgreSQL 事务提交。事件证据包含区域类型、发布
版本、标签、发生时车辆/人员、触发位置事件、前后稳定状态、确认点数和定位运行修订。唯一键
`(zone_type, zone_version_id, tag_id, event_type, anchor_location_event_id)` 保证相同历史顺序重放不会产生第二个业务事件。

`spatial_evaluation_queue` 以位置事件标识唯一，领取使用租约、`SKIP LOCKED` 和退避。状态表丢失时可按矿区、标签、发生时间、
摄入序号重建；重建再次命中相同事件唯一键，只恢复状态，不重复发布。配置发布只影响其有效时间内的新判定，默认不回溯重算；
管理员显式创建重放任务时必须给出矿区、区域版本、时间窗、原因和幂等键，时间窗上限固定，原始位置事实不可修改。

Outbox 只发布白名单 `realtime.spatial.event.created` v1。发布确认后推进状态，失败使用有界指数退避并保留 `DEAD` 证据。Redis
不是空间状态真相来源，空间状态恢复只依赖数据库和不可变运行快照。

## 6. API、权限与前端

控制面 API 位于 `/api/v1/mine/sites/{siteId}`，提供途径点、路线、围栏的分页、详情、创建草稿、修改草稿、发布和归档；所有
发布请求要求乐观版本并返回内容摘要。事件 API 提供固定水位分页、区域/对象/事件类型/时间过滤和单事件证据详情。重放 API 使用
`Idempotency-Key`，只允许管理员权限。

权限分为 `mine:spatial:view`、`mine:spatial:edit`、`mine:spatial:publish`、`mine:spatial:event:view` 和
`mine:spatial:replay`。菜单在“矿区管理”下新增“路线与围栏”，前端使用一个工作台的“途径点 / 路线 / 围栏 / 运行事件”页签，
避免新增多个相似菜单。编辑器先使用二维统一坐标表格与画布，发布前展示拓扑、有效期、引用和影响摘要；没有编辑权限时为纯只读。

业务页面继续遵守 Naive UI、UnoCSS、主题 token 和中英文治理。ECharts/画布颜色从 Naive UI theme 派生；不得在页面添加
`<style>`、内联 CSS 或硬编码颜色。实时事件断档继续复用现有 REST 快照后接 WebSocket 增量和 `RESYNC` 机制。

## 7. 可观测性与安全失败

指标只使用固定标签：队列处理结果/原因、区域类型、空间分类结果、事件类型、重放结果和 Outbox 状态；禁止组织、矿区、区域、
标签、车辆、人员、坐标或异常文本进入标签。告警覆盖快照持续失败、空间队列积压、过晚比例突增、Outbox DEAD、状态恢复失败和
重放长期运行。

空间快照非法时继续使用最后正确版本。单个区域几何非法不得激活整包新修订。Telemetry 暂时失败时重新投递，永久数据错误写
固定原因证据。停用空间事件只能停止评估消费者并保留队列、状态、事件和 Outbox，禁止清库或删除最后正确快照作为回退手段。

## 8. 自动化成功标准

- 管理库迁移、中文注释、跨矿区外键、版本排斥、发布不可变和几何约束集成测试通过；
- API 精确 RBAC、数据范围、乐观锁、发布摘要、引用检查和 OpenAPI 契约通过；
- 快照分页、摘要、原子激活和 last-known-good 包含三类空间版本；
- 射线法、圆形、高度、边界、连续点消抖、迟到排序、空闲刷新、进入/离开/停留和重放幂等测试通过；
- 状态、事件和 Outbox 事务一致，RabbitMQ 发布确认、重试、DEAD 和实时订阅测试通过；
- 前端加载/空/错/权限/发布确认/矿区切换/断档重同步/窄屏和主题治理通过；
- Maven、前端、Compose、Prometheus 和必要 Playwright 门禁通过；真实现场项继续单独列为 `DEFERRED`。

# 调度首页与系统运行监控设计

## 1. 决策

平台默认首页只面向矿区调度员和值班人员，回答“现场现在是否正常、哪里需要处理、数据是否可信”。数据库、Redis、RabbitMQ、网关和遥测服务等技术状态从首页移出，放入“系统管理 / 运行监控”，仅向具备独立运维权限的用户开放。

页面不根据 `admin` 等角色名称硬编码差异。首页作为登录后的公共生产入口；运行监控使用 `system:operations:view` 权限，由现有角色授权菜单控制可见性和接口访问。

## 2. 调度首页

### 2.1 首屏信息顺序

1. 运行结论：当前数据更新时间、数据是否新鲜、手动刷新。
2. 四项真实指标：登记设备、正常上报、数据中断、今日接收报文。
3. 需要关注：从遥测最新状态计算的数据中断和从未上报设备，按中断时长优先。
4. 设备接入态势：正常上报、数据陈旧、从未上报的构成和口径说明。
5. 最近 24 小时报文趋势：只展示真实入库消息，不用装饰性假曲线。
6. 常用入口：实时监控、设备台账和命令中心；入口按现有权限显示。

最近 24 小时固定返回 24 个整点桶，没有消息的小时补零。若刷新时遥测库暂不可用，页面保留本次会话内最后一次成功快照并明确标记数据已陈旧；首次加载即不可用时展示未知，不把未知伪装成零。

### 2.2 指标口径

- 登记设备：状态为 `ENABLED` 的设备数量。
- 正常上报：遥测最新状态在新鲜度窗口内更新的启用设备数量。
- 数据中断：有过遥测、但最新状态超过新鲜度窗口的启用设备数量。
- 从未上报：启用设备中不存在遥测最新状态的设备数量。
- 今日接收：矿区部署时区当天写入 `telemetry_inbox` 的消息数量。
- 数据新鲜度窗口：后端配置，默认 5 分钟；前端只展示后端返回的口径。

设备台账和遥测位于不同数据库。后端分别查询，再按设备 UUID 合并；不得跨库拼接 SQL。遥测库不可用时，登记设备仍可返回，但依赖遥测的指标标记为 `UNAVAILABLE`，前端不能把不可用误显示为 0。

`telemetry_inbox.received_at` 建立时间索引，保证今日计数、最近消息和 24 小时聚合不会随数据增长退化为全表扫描。

### 2.3 空状态和异常

- 没有登记设备：明确引导管理员先完成设备接入，不显示“系统正常”。
- 有设备但没有遥测：展示“从未上报”，并提供设备台账/实时监控入口。
- 遥测查询不可用：指标显示“暂不可用”，页面保留上一次成功数据并标记陈旧；本期首次加载失败时展示局部错误，不让整页白屏。
- 告警能力尚未实现，本期不伪造“活动告警 0”；待告警域交付后再加入待处置区。

## 3. 系统运行监控

运行监控位于“系统管理”目录下，路径 `/system/operations`，组件标识 `system-operations-monitor`，权限为 `system:operations:view`。

首版展示按需探测结果，不启动浏览器轮询，也不增加服务启动扫表任务：

- mine-server 进程；
- 业务 PostgreSQL；
- Redis；
- TimescaleDB 遥测查询连接；
- RabbitMQ 管理接口；
- mine-gateway 健康接口；
- mine-telemetry 健康接口。

每项返回 `UP`、`DEGRADED`、`DOWN` 或 `UNKNOWN`、检查时间、耗时和简短诊断。用户进入页面或点击刷新时才检查。后端对单个依赖设置短超时并隔离失败，一个依赖故障不能让整个接口失败。

数据库、Redis、RabbitMQ 和内部 HTTP 服务的探测并行发起并共享统一短截止时间，避免任一客户端较长的默认超时拖住整个管理接口。

## 4. 视觉与交互

采用项目 `.impeccable.md` 定义的明亮、克制工业控制台风格。所有颜色、边框、圆角、阴影、间距和明暗模式均来自 Naive UI 主题及项目现有原子类，不新增硬编码色值或页面私有主题。状态同时使用文字、图标和颜色。

首页不再使用四张完全相同的通用卡片和开发阶段 Step 组件。指标形成一条紧凑状态带，“需要关注”占据主要视觉区域，右侧放接入构成；趋势和快捷入口位于第二层。1366×768 下首屏应能看到运行结论、指标和至少三条异常设备；窄屏自动改为单列，不隐藏关键状态。

## 5. 数据流与安全

```text
调度首页 -> GET /api/v1/dashboard/operations
                 |-> 业务库：启用设备与设备名称
                 `-> TimescaleDB：最新状态、今日消息、24 小时桶

运行监控 -> GET /api/v1/system/operations
                 |-> 本进程 / PostgreSQL / Redis / TimescaleDB
                 |-> RabbitMQ Management API
                 `-> gateway / telemetry Actuator health
```

系统运行监控接口必须校验 `system:operations:view`。响应不得包含数据库地址、用户名、口令、完整异常堆栈或 RabbitMQ 凭证。调度首页只返回生产态势所需字段，不返回协议密钥等设备敏感信息。

## 6. 验收

- 首页不再出现 `Phase 0`、`待建设`、`等待服务接入`等研发阶段文案。
- 所有首页数字来自接口；不可用与零值可区分。
- 首页可以在 1366×768、1920×1080、窄屏和深色主题下使用。
- 运行监控只出现在系统管理下，未授权用户既看不到菜单也无法调用接口。
- 页面切换不白屏，不新增定时轮询，国际化和主题治理检查通过。

# Phase 2 通知控制面验收报告

> 验收日期：2026-07-21
>
> 验收分支：`feat/phase-0-foundation`
>
> 验收范围：内置 Provider 渠道、独立密钥、接收组与加密目标、受控模板、不可变升级策略、OpenAPI、精确 RBAC、管理员工作台和操作审计
>
> 当前结论：**通知控制面开发与非现场自动化验收通过；不代表真实通知送达、值班闭环或矿区生产放行**

## 1. 结论摘要

本切片把内置通知 Provider 从代码适配器推进为可由平台管理员维护的数据库控制面。管理员在“告警管理 → 通知渠道”统一入口中配置渠道、接收对象、模板和升级策略；敏感凭据与触达目标使用通知独立密钥加密，普通查询只返回安全摘要或脱敏值，独立回显权限和 `no-store` 响应用于受控读取并记录审计。

升级策略采用稳定聚合根、草稿和不可变发布快照。发布前会校验渠道、接收组、至少一个启用成员、模板渠道/事件类型和同优先级作用域冲突；后续修改必须派生新草稿，停止匹配通过归档完成。公开契约、后端枚举和数据库约束已统一使用 `EXTERNAL_CONTACT`，V62 会迁移旧 `EXTERNAL` 数据。

当前没有告警事务到通知事件的运行桥接，也没有投递账本、租约工作器、异步回执、送达状态或事件单运行时。真实 SMTP、企业 IM、Webhook、短信和电话没有执行；本报告不能作为供应商联调、现场网络、费用、送达率、值班响应或商业交付终验证明。

## 3. 管理员闭环证据

本地 HTTPS 环境使用管理员角色完成以下验收，未在报告中保存账号密码、真实供应商凭据或可用触达目标：

1. 验证“告警管理 → 通知渠道”菜单及渠道、接收对象、通知模板、升级策略四个页签可见。
2. 创建启用接收组和外部联系人邮箱；列表只显示脱敏目标，独立“查看真实目标”能回显并提示读取已写入审计。
3. 创建启用的 `ALARM_RAISED` 邮件模板，验证对象名称、保存按钮和必填提示使用各自文案，不再复用渠道文案。
4. 创建通用 Webhook 禁用草稿，验证完整地址和签名密钥加密保存；重新打开编辑抽屉时，具备独立权限的管理员可以受控回显并产生读取审计。
5. 公网 DNS 不可用的应用容器拒绝启用 Webhook，证明 HTTPS、精确白名单、DNS 与 SSRF 保护不会被前端绕过；该渠道保持禁用。
6. 创建不会在保存阶段联网的 SMTP 验收渠道，发布只匹配不存在规则编码的策略 v1；发布先因组内成员禁用被拒绝，启用成员后通过依赖校验并生成不可变快照。
7. 验证完成后立即归档策略并停用 SMTP/Webhook 验收渠道，避免后续误匹配；全程没有创建告警或调用任何 Provider。

`sys_operation_log` 已记录 `CREATE_NOTIFICATION_RECIPIENT_GROUP`、`CREATE_NOTIFICATION_RECIPIENT`、`READ_NOTIFICATION_RECIPIENT_TARGET`、`CREATE_NOTIFICATION_TEMPLATE`、`CREATE_NOTIFICATION_CHANNEL`、`READ_NOTIFICATION_CHANNEL_SECRETS`、`CREATE_NOTIFICATION_POLICY`、`PUBLISH_NOTIFICATION_POLICY`、`ARCHIVE_NOTIFICATION_POLICY` 和渠道停用更新，且结果为 `SUCCESS`。

## 5. 关键运行不变量

1. 平台提供什么 Provider，管理员才能配置什么 Provider；数据库内容不能加载平台未发行代码。
2. 通知密钥独立于人员密钥，凭据、目标和密钥哨兵必须作为同一恢复集合管理。
3. 普通列表和详情不得返回凭据或真实目标；敏感读取必须具备独立权限、禁止缓存并留下审计。
4. 禁用渠道可以保存未完成配置；启用渠道必须通过 Provider 字段和安全组合校验。
5. 发布权限独立于策略编辑权限；发布前所有运行依赖必须启用且类型匹配。
6. 已发布版本不可原地修改或删除；修改通过新草稿和更高版本，停止匹配通过归档。
7. `SUBMITTED` 只表示 Provider 受理，不能解释为终端 `DELIVERED`；未知结果不得盲目重发可能计费的短信或电话。
8. 当前控制面不会自行投递；没有可靠账本、工作器和回执前，不得对外宣称自动通知升级闭环已经完成。

## 6. 部署、恢复与回退边界

生产发布必须同时准备新后端、匹配前端制品、V53～V62 迁移和原通知密钥。Standalone 事实备份故意排除 secret，部署方需在独立密码库或加密离线介质备份通知密钥。恢复顺序为密钥、PostgreSQL、单个服务启动校验、敏感读取抽查和扩容；密钥不匹配必须失败关闭。

迁移只向前执行。V62 后只认识旧 `EXTERNAL` 枚举的应用不能直接回退；优先发布前向修复，确需回退必须在维护窗口同时转换数据与约束。策略业务回退使用新草稿、更高发布版本、归档或停用渠道，不修改数据库历史快照。

详细步骤见 [通知 Provider 配置与安全运行手册](../runbooks/notification-providers.md)。

## 7. 生产启用前置门禁

- 为真实供应商账号配置最小权限、IP/域名出口、签名/模板/号码资质、费用上限、退订和隐私要求；
- 建立通知事件、幂等投递账本、租约工作器、重试/未知结果策略、异步回执、送达查询和事件单闭环；
- 对每类渠道完成真实单条发送、回执对账、故障注入、限流、配额、账单和重复发送演练；
- 完成通知密钥与 PostgreSQL 一致恢复、密钥轮换方案、HA、断电、网络分区和容量验收；
- 完成值班排班、升级时限、确认/关闭职责、审计复核和 24/72 小时长稳签字。

以上项目完成前，通知控制面可以继续用于产品化开发和现场配置准备，但不能作为“可直接上线卖”的最终送达闭环。
